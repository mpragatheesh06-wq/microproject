1. Executive Summary

SmartRoute is a full-stack emergency medical response dispatch application designed to drastically minimize Emergency Response Times (ETA). By leveraging core computer science principles—specifically Design and Analysis of Algorithms (DAA) graph traversal (Dijkstra's Shortest Path) with dynamic live rerouting—the system coordinates patients, ambulances, and hospital trauma facilities in real-time.

🎯 Core Project Objectives
  • Immediate Dispatch Without Sign-up: Patients can trigger emergency requests in seconds without entering credentials or downloading apps.
  • Condition-Driven Medical Kit Recommendation: Dynamic triage algorithm suggests the appropriate onboard emergency medical kit (e.g., cardiac defibrillators, burn packs, fracture kits).
  • Dynamic Patient Hospital Selection & Rerouting: Allows patients or guardians to select their preferred hospital, automatically recalculating the ambulance's route in real time.
  • Hybrid Backend Storage: Dual-mode architecture utilizing Supabase (PostgreSQL) with automatic offline fallback to Browser LocalStorage.

4. Algorithmic Foundation (DAA Implementation)

The dispatch routing engine models the emergency transportation network as a directed weighted graph G = (V, E), where vertices represent locations and edges represent roads with dynamic weight factors.

Edge Weight W(u, v) = Distance(u, v) × Traffic_Multiplier(u, v)

To find the optimal trajectory from the dispatched ambulance unit through the patient location to the selected hospital, Dijkstra's algorithm is executed:

// Core Relaxation Step in DAA Visualizer for (const neighbor of graph[currNode]) { const edgeWeight = neighbor.dist * neighbor.traffic; const altDistance = dist[currNode] + edgeWeight; if (altDistance < dist[neighbor.to]) { dist[neighbor.to] = altDistance; prev[neighbor.to] = currNode; priorityQueue.insert({ node: neighbor.to, priority: altDistance }); } }
Algorithm Time Complexity Space Complexity Role in SmartRoute
Dijkstra (Min-Heap) O((V + E) log V) O(V) Primary path calculation from patient to nearest available trauma centers.
A* Search (Heuristic) O(E) (Best) / O(b^d) O(V) Direct ambulance dispatch when GPS coordinates provide Euclidean distance heuristics.
Dynamic Rerouting O(V log V) O(V) Re-plans path from current ambulance position upon patient hospital switch.

5. Backend Connection & Database Architecture

SmartRoute features a dual-mode abstraction layer implemented in scripts/supabase-client.js. The application automatically determines whether to send queries to a live cloud Supabase instance or save locally.

Database Relational Model (PostgreSQL / Supabase)

-- 1. HOSPITALS TABLE CREATE TABLE hospitals ( id UUID PRIMARY KEY DEFAULT uuid_generate_v4(), name VARCHAR(255) NOT NULL, latitude NUMERIC(10, 6) NOT NULL, longitude NUMERIC(10, 6) NOT NULL, available_er_beds INT DEFAULT 10, icu_available BOOLEAN DEFAULT TRUE, hospital_type VARCHAR(100), status VARCHAR(50) DEFAULT 'active' ); -- 2. AMBULANCES TABLE CREATE TABLE ambulances ( id UUID PRIMARY KEY DEFAULT uuid_generate_v4(), unit_code VARCHAR(50) UNIQUE NOT NULL, driver_name VARCHAR(100) NOT NULL, driver_phone VARCHAR(50), current_status VARCHAR(50) DEFAULT 'Available', kit_loaded TEXT ); -- 3. INCIDENTS TABLE CREATE TABLE incidents ( id UUID PRIMARY KEY DEFAULT uuid_generate_v4(), ticket_code VARCHAR(50) UNIQUE NOT NULL, patient_name VARCHAR(150), emergency_type VARCHAR(100) NOT NULL, severity_level VARCHAR(20) NOT NULL, selected_hospital_id UUID REFERENCES hospitals(id), assigned_ambulance_id UUID REFERENCES ambulances(id), recommended_kit JSONB, status VARCHAR(50) DEFAULT 'Dispatched', created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP );
